= 概述
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
灾难恢复是每个 VMware 管理员最关心的问题。因为 VMware 将整个服务器封装到一系列组成虚拟机的文件中；管理员利用基于块存储的技术（如克隆、快照和副本）来保护这些虚拟机。ONTAP 阵列提供内置复制以将卷数据从一个站点传输到另一个站点，从而将驻留在指定数据存储 LUN 上的虚拟机传输到另一个站点。NetApp Disaster Recovery 与 vSphere 集成并自动化整个工作流程，以便在发生灾难时实现无缝故障转移和故障回复。通过将存储复制与智能自动化相结合，管理员现在不仅可以配置、自动化和测试灾难恢复计划，还可以在发生灾难时轻松运行这些计划。

VMware vSphere 环境中 DR 故障转移最耗时的部分是在 DR 站点执行清点、注册、重新配置和启动虚拟机所需的步骤。理想的解决方案既具有低 RPO（以分钟为单位），又具有低 RTO（以分钟到小时为单位）。  DR 解决方案中经常被忽视的一个因素是定期有效地测试 DR 解决方案的能力。

要构建 DR 解决方案，请牢记以下因素：

* 恢复时间目标 (RTO)。  RTO 是指企业从灾难中恢复的速度，或者更具体地说，是执行恢复过程以使业务服务再次可用所需的时间。
* 恢复点目标 (RPO)。  RPO 是指恢复的数据相对于灾难发生的时间而言，可供使用的时间。
* 可扩展性和适应性。该因素包括随着需求的增加而逐步增加存储资源的能力。
