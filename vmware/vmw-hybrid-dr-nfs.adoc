[[netapp-disaster-recovery-for-nfs-datastores]]
== NFS 数据存储的 NetApp Disaster Recovery

[role="lead"]
通过从生产站点到灾难恢复站点的块级复制来实现灾难恢复是一种有弹性且经济高效的方法，可以保护工作负载免受站点中断和数据损坏事件（例如勒索软件攻击）的影响。使用NetApp SnapMirror复制，在具有 NFS 数据存储的本地ONTAP系统上运行的 VMware 工作负载可以复制到位于指定恢复数据中心的另一个ONTAP存储系统，该数据中心也部署了 VMware。

本文档的这一部分描述了 NetApp Disaster Recovery 的配置，以便为本地 VMware 虚拟机设置到另一个指定站点的灾难恢复。作为此设置的一部分，控制台代理将载入 ONTAP 阵列、定义站点并关联 VMware vCenter。此外，本文档详细介绍了如何配置站点之间的复制以及如何设置和测试恢复计划。最后一部分包含有关执行完整站点故障转移的说明，以及如何在主站点恢复并重新上线时进行故障恢复。

利用灾难恢复（NetApp Data Services 的一部分），公司可以轻松发现其本地 VMware vCenters 和 ONTAP 存储。然后，组织可以创建资源组、创建灾难恢复计划、将其与资源组关联，以及测试或执行故障转移和故障回复。SnapMirror 提供存储级块复制，以使两个站点通过增量更改保持最新，从而实现最多 5 分钟的恢复点目标（RPO）。此外，还可以模拟灾难恢复过程，而不会影响生产或产生额外的存储成本。

灾难恢复利用 ONTAP 的 FlexClone 技术从灾难恢复站点上的上次复制快照创建 NFS 数据存储的节省空间的副本。完成灾难恢复测试后，客户可以轻松删除测试环境，而不会影响实际复制的生产资源。在实际故障转移的情况下，灾难恢复会协调所有必要的步骤，只需单击几下即可在指定的灾难恢复站点上自动启动受保护的虚拟机。该服务还将反转与主站点的 SnapMirror 关系，并在需要时将任何更改从辅助站点复制到主站点，以进行故障回复操作。与其他众所周知的替代方案相比，所有这些功能的成本仅为一小部分。

NOTE: 有关用于灾难恢复的 vCenter Server、ESXi 和 ONTAP 的最新信息和支持版本，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["灾难恢复支持的配置"]。



[[getting-started]]
=== 入门

要开始使用 NetApp Disaster Recovery，请使用 NetApp Console，然后访问该服务。

. 登录到 Console。
. 从控制台左侧导航栏中，选择保护 > 灾难恢复。
. 此时将显示灾难恢复仪表板。
+
image:dr-draas-nfs-002.png["该图显示输入/输出对话框或表示书面内容"]



在配置灾难恢复计划之前，请确保满足以下先决条件：

* 已部署控制台代理。
* 代理具有到源和目标 vCenter 以及存储系统的连接。
* 具有启用 NFS 服务的 SVM 的 ONTAP 集群可用。
* 在控制台中添加了托管适用于 VMware 的 NFS 数据存储的本地 NetApp 存储系统。
* 使用 DNS 名称时应该进行 DNS 解析。否则，请使用 vCenter 的 IP 地址。
* SnapMirror复制是为指定的基于 NFS 的数据存储库卷配置的。
* 确保环境具有受支持的 vCenter Server 和 ESXi 服务器版本。


一旦源站点和目标站点之间建立了连接，请继续执行配置步骤，这需要几次点击和大约 3 到 5 分钟的时间。


NOTE: NetApp 建议在目标站点或第三个站点中部署控制台代理，以便控制台代理可以通过网络与源和目标资源进行通信。

[[configuring-storage-replication-between-source-site-array-and-destination-site-array]]
=== 配置源站点阵列和目标站点阵列之间的存储复制

SnapMirror 在 NetApp 环境中提供数据复制功能。SnapMirror 复制基于 NetApp Snapshot 技术构建，效率极高，因为它仅复制自上次更新以来已更改或新增的块。SnapMirror 可通过 NetApp OnCommand System Manager 或 ONTAP CLI 轻松配置。NetApp Data Services 还会创建 SnapMirror 关系，前提是事先配置了集群和 SVM 对等关系。

对于主存储未完全丢失的情况，SnapMirror 提供了一种重新同步主站点和灾难恢复站点的有效方法。SnapMirror 可以重新同步两个站点，只需简单地反转 SnapMirror 关系，即可将更改或新数据从灾难恢复站点传回主站点。这意味着灾难恢复中的复制计划可以在故障切换后向任一方向重新同步，而无需重新复制整个卷。如果反向重新同步关系，则仅将自上次成功同步快照副本后写入的新数据发送回目标。


NOTE: 如果已通过 CLI 或 System Manager 为该卷配置 SnapMirror 关系，NetApp Data Services 将提取该关系并继续其余的工作流操作。

添加源站点和目标站点后，灾难恢复将执行自动深度发现并显示虚拟机以及关联的元数据。灾难恢复还会自动检测虚拟机使用的网络和端口组，并填充它们。

[[test-failover]]
=== 测试故障转移

灾难恢复中的测试故障转移是一种操作过程，允许 VMware 管理员在不中断其生产环境的情况下完全验证其恢复计划。在测试故障转移期间，灾难恢复会在 DR 存储系统上创建复制的 NFS 数据存储卷的节省空间的 NetApp FlexClone 副本。然后将这些 FlexClone 卷挂载到 DR 站点的 ESXi 主机上，并在隔离的测试网络中开启虚拟机电源。此过程允许管理员验证其灾难恢复计划在发生实际灾难时能否按预期运行。

image:dr-draas-nfs-024.png["该图显示输入/输出对话框或表示书面内容"]

灾难恢复在测试故障转移操作中加入了选择快照这一可选功能。此功能允许 VMware 管理员验证最近在环境中所做的任何更改是否已复制到目标站点，从而确保这些更改在测试期间存在。此类更改包括虚拟机客户机操作系统的补丁

image:dr-draas-nfs-025.png["该图显示输入/输出对话框或表示书面内容"]

当 VMware 管理员运行测试故障切换操作时，灾难恢复会自动执行以下任务：

* 触发SnapMirror关系，使用生产站点上所做的任何最新更改来更新目标站点上的存储。
* 在 DR 存储阵列上创建FlexVol卷的NetApp FlexClone卷。
* 将FlexClone卷中的 NFS 数据存储库连接到 DR 站点的 ESXi 主机。
* 将虚拟机网络适配器连接到映射期间指定的测试网络。
* 按照 DR 站点的网络定义重新配置 VM 客户操作系统网络设置。
* 执行复制计划中存储的任何自定义命令。
* 按照复制计划中定义的顺序启动虚拟机。
+

[[cleanup-failover-test-operation]]
=== 清理故障转移测试操作

清理故障转移测试操作在复制计划测试完成并且 VMware 管理员响应清理提示后发生。

image:dr-draas-nfs-027.png["该图显示输入/输出对话框或表示书面内容"]

此操作将虚拟机 (VM) 和复制计划的状态重置为就绪状态。

当 VMware 管理员执行恢复操作时，灾难恢复将完成以下过程：

. 它关闭用于测试的FlexClone副本中的每个恢复的虚拟机。
. 它会删除在测试期间用于呈现恢复的虚拟机的 FlexClone卷。




[[planned-migration-and-fail-over]]
=== 计划迁移和故障转移

灾难恢复有两种执行真正故障转移的方法：计划迁移和故障转移。第一种方法，即计划迁移，将虚拟机关闭和存储复制同步纳入流程，以恢复或有效地将虚拟机移动到目标站点。计划迁移需要访问源站点。第二种方法，即故障转移，是一种计划内/计划外故障转移，其中虚拟机在目标站点从能够完成的最后一个存储复制间隔进行恢复。根据解决方案中设计的 RPO，在 DR 场景中可能会出现一定程度的数据丢失。

image:dr-draas-nfs-028.png["该图显示输入/输出对话框或表示书面内容"]

当 VMware 管理员执行故障切换操作时，灾难恢复会自动执行以下任务：

* 中断并故障转移NetApp SnapMirror关系。
* 将复制的 NFS 数据存储连接到 DR 站点的 ESXi 主机。
* 将 VM 网络适配器连接到适当的目标站点网络。
* 按照目标站点的网络定义重新配置 VM 客户操作系统网络设置。
* 执行复制计划中存储的任何自定义命令（如果有）。
* 按照复制计划中定义的顺序启动虚拟机。


image:dr-draas-nfs-029.png["该图显示输入/输出对话框或表示书面内容"]



[[failback]]
=== 故障回复

故障回复是一种可选过程，可在恢复后恢复源站点和目标站点的原始配置。

image:dr-draas-nfs-030.png["该图显示输入/输出对话框或表示书面内容"]

当 VMware 管理员准备将服务恢复到原始源站点时，他们可以配置并运行故障回复程序。

*注意：* 灾难恢复在反转复制方向之前，将任何更改复制（重新同步）回原始源虚拟机。此过程从已完成故障转移到目标的关系开始，涉及以下步骤：

* 关闭并取消注册虚拟机，并卸载目标站点上的卷。
* 打破原始源上的SnapMirror关系，使其变为读/写。
* 重新同步SnapMirror关系以逆转复制。
* 在源上安装卷，启动并注册源虚拟机。


有关访问和配置灾难恢复的详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["了解适用于 VMware 的 NetApp Disaster Recovery"]。
